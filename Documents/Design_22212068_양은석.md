## <a id="intro"></a>1. Introduction

어느 지역에 거주할지 결정할 때 범죄 발생률, 의료시설, 학교, 편의시설 등 다양한 생활 지표를 개별적으로 확인해야 하는 번거로움이 존재한다. 관련 정보가 여러 공공기관에 분산되어 있어 한눈에 비교하기 어렵고, 구/군 단위를 넘어 동 단위의 세밀한 분석은 더욱 어려운 실정이다. 이를 해결하기 위해 본 프로젝트는 공공 API로부터 생활 지표 데이터를 자동 수집·정규화하고, 카카오맵 기반의 웹 인터페이스에서 지역별 종합 점수를 시각적으로 제공하는 주거지 평가 시스템을 개발하였다.

본 문서는 Analysis에 이은 Design 단계의 문서로, class diagram, sequence diagram, state machine diagram을 제시하고 각 diagram에 대한 설명을 기술한다. 추가로 implementation requirements를 기술하여 본 시스템을 구현하기 위한 소프트웨어 및 하드웨어 요구사항을 명시한다. 본 시스템은 Java 기반의 데이터 수집 모듈과 HTML/JavaScript 기반의 프론트엔드로 구성되며, 데이터 수집 자동화에는 GitHub Actions를 활용한다. 수집 범위는 대구광역시를 시작으로 부산광역시·서울특별시로 확장하였다.

## <a id="smd"></a>4. State machiine diagram

<img width="608" height="711" alt="StateMachineDG" src="https://github.com/user-attachments/assets/e888ef9d-abfa-4b14-a3eb-2929d5bfac77" />

시스템은 WorkflowDispatch(수동 실행) 또는 Schedule(자동 스케줄)로 시작하며 두 진입점 모두 DB Initialized 상태로 진입한다. DB Initialized 상태에서는 Gradle 빌드를 수행한다.빌드가 완료되면 Collecting 상태로 진입하며, 내부적으로 시작점에서 4개를 순차 수집한다. 수집 중 오류가 발생하면 [error] 전이를 통해 Notified Error 상태로 이동하여 Discord 에러 알림을 전송한다. 모든 수집이 정상 완료되면 종료 포인트를 거쳐 Saving 상태로 전이된다.

Saving 상태 진입 시 calculateScore를 실행하여 min-max 정규화로 점수를 계산하고, 이후 RegionStore.save()를 통해 regions.json 파일에 데이터를 저장한다. 저장이 완료되면 DiffChecked 상태로 이동하여 git diff로 regions.json의 변경 여부를 확인한다. 변경이 없으면 [!diff] 전이를 통해 Notified Info 상태로 이동하여 Discord에 변경 없음 알림을 전송한다. 변경이 있으면 [diff] 전이를 통해 Committed 상태로 이동하여 자동 커밋 및 푸시를 수행하고, 이어서 Notified Success 상태로 이동한다. Notified Success 상태에서는 Discord에 성공 알림을 전송하며 GitHub Pages 배포를 수행한다. 배포가 완료되면 종료 포인트를 통해 Page Deployed 컨테이너로 진입한다.

Page Deployed 컨테이너는 종료 없이 순환하는 프론트엔드 구간이다. 시작점에서 Idle 상태로 진입하며, deploy 전이를 통해 Setting 상태로 이동한다. Setting 상태 진입 시 초기 설정을 초기화하고, Map View 상태와 함께 지도와 오버레이를 구성한다. 사용자가 점수를 확인하면 view score 상태로 전이되며, 이후 다시 Setting 상태로 돌아가 지역 변경이나 가중치 조정을 반복할 수 있다.

## <a id="ir"></a>5. Implementation requirements

- **외부 공공 API 연동 필수**
    - 공공데이터포털
    - NEIS
- **API 인증 키 관리**
    - 환경변수 기반
    - 미설정 시 런타임 예외 발생
- **데이터 수집 안정성**
    - API 요청 간 딜레이 적용
    - 타임아웃 설정 (connect/read timeout)

## <a id="glossary"></a>6. Glossary

| Term | Description |
| --- | --- |
| **RegionStore** | 시도/구/동 단위의 지표 데이터와 점수를 저장하는 중앙 데이터 저장소 |
| **Collector** | 외부 API로부터 특정 지표 데이터를 수집하는 모듈 |
| **Normalization** | 서로 다른 지표를 비교 가능하도록 0~100 범위로 변환하는 과정 |
| **Webhook** | 시스템 이벤트를 외부 서비스(Discord)로 전송하는 방식 |
